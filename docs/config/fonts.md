## Embedding the terminal font

SVGs generated by rich-codex are typeset in [Fira Code](https://github.com/tonsky/FiraCode).
Rich writes a `@font-face` rule pointing at a `local("FiraCode-Regular")` source with a CDN
URL to fall back on, so the image contains no font of its own.

That works in a browser tab, but not where most people actually see these images.
Markdown renderers put images in an `<img>` tag, and SVGs inside `<img>` are rendered in
_secure static mode_ — no external resource is ever fetched, whatever the CSS says.
GitHub goes further and proxies images through camo, so the CDN is doubly out of reach.

That leaves `local()` as the only source that can resolve, and the image is then only
correct on machines that happen to have Fira Code installed. Everywhere else the browser
substitutes another monospace font. Rich places every chunk of text at an absolute `x`
coordinate calculated from the character width it expects, so the substituted glyphs
drift within each chunk, and box-drawing characters come apart at the seams.

So rich-codex puts the font _inside_ the SVG, as a base64 data URI. A data URI isn't an
external fetch, so `<img>` mode is happy to use it and the image looks the same for
everyone. Only the characters the image actually renders are embedded, and the bold
weight is left out when nothing in the image is bold.

This is on by default. Turn it off with `--no-embed-font` / `$EMBED_FONT` /
`embed_font` (CLI, env var, action/config) to go back to Rich's linked font:

```yaml
embed_font: false
```

Here's the same command rendered both ways. If you have Fira Code installed they look
identical; if you don't, only the first one is still Fira Code — the giveaway being the
ligatures, `->` and `!=` drawn as `→` and `≠`:

<!-- prettier-ignore-start -->
Default:

```markdown
<!-- RICH-CODEX { terminal_width: 70, hide_command: true } -->
![`rich --print "[bold]Fira Code ligatures[/]: -> != >= ... and box drawing" --panel rounded --force-terminal`](../img/embed-font.svg)
```
![rich --print](../img/embed-font.svg)

With `embed_font` set to `false`:

```markdown
<!-- RICH-CODEX { terminal_width: 70, hide_command: true, embed_font: false } -->
![`rich --print "[bold]Fira Code ligatures[/]: -> != >= ... and box drawing" --panel rounded --force-terminal`](../img/embed-font-off.svg)
```
![rich --print](../img/embed-font-off.svg)
<!-- prettier-ignore-end -->

How badly the second one degrades depends on which font your browser reaches for instead.
A substitute with the same character width mostly just looks wrong; one with a different
width pulls the columns out of line and leaves gaps between box-drawing characters.

<!-- prettier-ignore-start -->
!!! note
    This only affects SVG output. PNGs are rasterised by [resvg](https://github.com/linebender/resvg),
    and no rasteriser implements `@font-face` — they all read fonts from the machine doing
    the rendering. rich-codex hands resvg its own bundled copy of Fira Code instead, so PNGs
    come out right without it installed either. The only exception is the window title, which
    Rich sets in Arial and which falls back to whatever sans-serif the machine has.
<!-- prettier-ignore-end -->

## File size

Embedding is not free. Expect somewhere between 10 KB and 30 KB per image, depending on
how many distinct characters the image uses and whether any of them are bold:

| Image                                     | `embed_font: false` |  Default |
| ----------------------------------------- | ------------------: | -------: |
| The panel above (31 characters, bold)     |              3.7 KB |  30.1 KB |
| `rich-codex --help` (70 characters, bold) |             73.0 KB | 101.3 KB |

Turn it off if you'd rather keep the files small and you know your readers have Fira Code,
or if you're only using the PNG output.

<!-- prettier-ignore-start -->
!!! tip
    Ligatures are kept, so `!=` and `->` render as `≠` and `→` exactly as they do in a
    terminal running Fira Code. They're most of the cost — Fira Code has hundreds of them,
    and keeping them roughly doubles the size of the embedded subset.
<!-- prettier-ignore-end -->

## Reproducibility

The embedded font is byte-for-byte reproducible: the same command with the same output
always produces the same bytes, so re-running rich-codex in CI doesn't churn the diff on
images that haven't changed.

Different `fonttools` releases do subset the same font slightly differently, so an upgrade
changes what rich-codex would generate. It doesn't rewrite anything, though: the embedded
font is ignored when an image is compared against the one already saved, so images are only
rewritten when their _content_ changes, and they carry whatever subset they were built with
until then. That comparison is also why [`min_pct_diff` and `skip_change_regex`](ignoring_changes.md)
still measure the output rather than the font.
